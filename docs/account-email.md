# 驗證與密碼重設郵件

電子郵件驗證與系統密碼重設皆使用原本設定的寄件帳號、郵件佇列與寄件工作程序，不再使用 Firebase Authentication 郵件。不需服務帳戶 JSON、Firebase 郵件範本或自訂動作網址設定；Google、GitHub、Microsoft 的外部登入服務保留。

## 更新 API

在樹莓派執行：

```bash
curl -fsSL https://raw.githubusercontent.com/easonlin2013927/704-class-system/main/deploy/update-api.sh -o /tmp/704-update-api.sh
bash /tmp/704-update-api.sh
```

成功輸出包含 `DEPLOY_OK v0.41.1`。既有寄件帳號與郵件工作程序需維持啟用；腳本沿用原本主機環境設定，不會要求 Firebase 郵件金鑰或修改寄件者。

## 使用方式

- 所有登入與安裝入口提供「忘記密碼／重設密碼」。輸入系統帳號及已驗證信箱後，符合條件的要求會加入原寄件佇列。受理訊息不透露帳號是否存在，也不代表已送達。
- 自行新增的信箱使用郵件連結驗證。收到信後按連結，再於公開確認頁按「確認驗證」，完成後回到設定重新檢查。
- 重設郵件連結開啟後設定新系統密碼；成功後舊登入工作階段失效。一般改密碼或管理員改密碼也會作廢舊重設連結。
- 連結有效 30 分鐘、只能使用一次，並綁定帳號與當時的信箱地址。已過期、已刪除、已變更、已停用或對應不唯一的信箱無法重設。
- 驗證與重設是必要帳號郵件，沿用既有驗證信的規則，不受一般外部通知開關或通知偏好影響；仍受原寄件服務的額度、重試與有效期限限制。
- 系統密碼只在原伺服器保存雜湊，不修改 Google、GitHub 或 Microsoft 帳戶密碼。

## 未收到信件

檢查收件匣與垃圾郵件，再由管理員查看原寄件服務與郵件佇列狀態。請勿把「加入佇列」視為「寄送成功」或「收件者已閱讀」。逾期連結請重新要求寄送，不要分享含 state 或一次性代碼的完整網址。

實際寄信驗收需在 API 更新後進行：使用測試帳號完成新增信箱驗證，再登出要求重設，確認新密碼可登入、舊密碼失效。瀏覽器 mock 測試不等於真實郵件送達。
